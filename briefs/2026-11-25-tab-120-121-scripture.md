## Task

Start the 1.0.2 foundations work (parent [TAB-128](https://linear.app/loomlogiclabs/issue/TAB-128/redesign-release-102-foundations-analytics-scripture-and-timing-fixes); plan: [Tablet Notes redesign plan](https://linear.app/loomlogiclabs/document/tablet-notes-redesign-plan-968ebcacecea)) with the two scripture-reliability bugs that block weekly reminders. TAB-128 requires each to close with its own PR and regression tests.

TAB-120: the summarize prompt asks every tier for a fixed set of sections (Main Scripture Text, Brief Summary, Key Points, Memorable Elements, Scripture References, and the rest listed in the issue), but the model often returns narrative prose and drops Scripture References. Both the client `SummaryRetryService` and the durable reaper hit the same `/api/summarize` endpoint, so the fix is in `tablet-notes-api/netlify/functions/summarize.js` (system prompt and `chat.completions.create` call). The issue lists three options and Baise has not picked one: (1) lower the default temperature to 0.2–0.3 and keep the prompt; (2) make Scripture References mandatory in the response contract ("always include, write 'None stated' if empty"), validate required headings, and retry once on a miss; (3) move to structured output (JSON schema) and render the sections server-side. Choose the smallest change that meets the 20-of-20 acceptance below, and record the choice in the PR and in `.ratchet/DECISIONS.md`. If you take option 3 (a response-contract change), say so clearly in the PR. Out of scope for this issue: reading spoken references out of transcripts (that is TAB-121) and the TAB-119 reminder code itself.

TAB-121: `ScriptureAnalysisService` only matches the written shape `Book chapter:verse`, so spoken forms in transcripts are missed, and a written reference that follows another word on the same line ("in Romans 8:28") is also dropped because the book pattern swallows the preceding word. Fix both in `TabletNotes/TabletNotes/Services/ScriptureAnalysisService.swift` (`patterns`, `parseMatch`, `isValidBibleBook`) as the issue describes: add the spoken patterns, normalize to the existing `ScriptureReference`, keep `raw` as the matched text, and anchor the book name to the known book list. Callers (`RecordingView`, `ClickableScriptureText`, `BibleFAB`, `ScriptureReminderPlanner`) should keep working, with the only product change being that those references are actually found. Out of scope: prompt or model changes on the backend (TAB-120).
