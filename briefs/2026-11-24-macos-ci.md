# Brief: Add macOS CI builds for the iOS app

**Project:** Tablet Notes
**Created:** 2026-11-24
**Status:** open

## Task

Add a GitHub Actions workflow that, on every pull request and every push to `main`, builds and tests the Tablet Notes iOS app on a real Mac so Linux agents can use the run as evidence. There are no existing workflows under `.github/workflows/` and no Xcode Cloud config (`ci_scripts/`), so use a GitHub-hosted `macos-*` runner. Do not adopt Xcode Cloud or a paid runner in this brief.

The workflow should run, from `TabletNotes/`, `xcodebuild build` and `xcodebuild test` for the shared `TabletNotes` scheme (`TabletNotes/TabletNotes.xcodeproj`, test plan `TabletNotes/TabletNotes.xctestplan`) on an iOS Simulator. Use a destination by device name and OS (for example `platform=iOS Simulator,name=iPhone 16,OS=18.5` or whatever 18.5-or-newer simulator the selected image actually has). Do not hard-code the local simulator UUID from `AGENTS.md`. Disable code signing (`CODE_SIGNING_ALLOWED=NO` or equivalent). Cache Swift package checkouts. Upload the `.xcresult` bundle and the `xcodebuild` log as a workflow artifact.

Constraints the workflow has to satisfy:

- The project and test targets set `IPHONEOS_DEPLOYMENT_TARGET` to 18.5 (the app target still says 17.6; 18.5-or-newer is required or the build fails). The project was created with Xcode 16.4; the shared scheme's `LastUpgradeVersion` is 2600, and recent local verification used an iPhone 16 Pro / iOS 26.2 simulator. Pick a runner image and Xcode version that can boot an iOS 18.5+ simulator, and write the exact runner label and `xcodebuild -version` in the PR.
- Run `TabletNotesTests` only. Do not include `TabletNotesUITests` in this first workflow.
- `docs/OPERATING-MANUAL.md` §3 lists two pre-existing failures on `main`: `SyncServiceMergeTests/syncDataIncludesOnlyDirtyChildScopesForExistingRemoteSermon`, and `SermonServiceSaveTests` recovery tests that pass in isolation and flake together. Exclude those from the CI test invocation (named, with a comment pointing at §3). Do not "fix" them in this PR. Use a fresh simulator so leftover recording audio cannot poison the `SermonService*` suites.
- `Package.resolved` is gitignored, so versions resolve from the project ranges (supabase-swift ≥ 2.5.1, firebase-ios-sdk ≥ 12.9.0, GoogleSignIn-iOS ≥ 7.0.0). Cache `SourcePackages` or the equivalent so repeats are not a full download.
- The app calls `FirebaseApp.configure()` at launch, and a prior branch's test host crashed when `GoogleService-Info.plist` was missing. `TabletNotes/.gitignore` ignores `*.plist` except `Info.plist`, and `Config.plist` plus `AssemblyAIKey.swift` are also gitignored. The workflow must compile and test without real secrets, API keys, or a production Firebase file. Generate or copy a clearly fake placeholder config in the job if the test host needs a plist, and never print secret or env values. Do not add a service-role key or any new credential to the repo.
- Do not edit `project.pbxproj` by hand (`fileSystemSynchronizedGroups` owns membership). Do not mark this workflow as a required status check unless Baise says so.
- Follow the Ratchet PR rules below. The Builder should run on Grok and the Verifier on Composer, unless Baise says otherwise.

## Complete means

- [ ] A workflow file exists under `.github/workflows/` and triggers on pull requests and on pushes to `main`.
- [ ] A PR run shows a green macOS job that built the `TabletNotes` scheme and ran `TabletNotesTests` (with the two §3 known failures excluded) on an iOS 18.5+ Simulator, with a link to that run.
- [ ] On a throwaway branch, a deliberately failing unit test makes the same job fail red (link). That failing change is then reverted or the branch is discarded so it does not land.
- [ ] The uploaded artifact can be downloaded from the green run, and its name is recorded.
- [ ] The wall-clock duration of the green run is recorded.

## Evidence required

- URL of the green PR (or `main`) workflow run, and the job name.
- URL of the deliberately failing run, plus confirmation that the failing change was reverted or the throwaway branch was not merged.
- Artifact name, and confirmation it downloaded and contains the `.xcresult` and/or the `xcodebuild` log.
- Runner label, `xcodebuild -version`, simulator destination used, and the green run's duration.
- The usual Ratchet PR body (What changed / Shape & why / Verification / Residue / Handoff), with `.ratchet/STATE.md` updated.

## Ratchet repos

If the repo has `.ratchet/`, follow its AGENTS.md:
- Update `.ratchet/STATE.md`: tag the PR `[open PR #N]` and update Last handoff.
- Append medium-impact decisions to `.ratchet/DECISIONS.md` (append only; supersede, never edit).
- Write the PR body in five sections: What changed / Shape & why / Verification (split RAN / READ / ASSUMED / INCONCLUSIVE; ASSUMED never empty) / Residue / Handoff.
- Bug fixes include the `RRR: PROVEN` line from rrr.sh.
- Any skipped step is written as `skip: <reason>`.
- The Verifier will fail PRs missing these.
